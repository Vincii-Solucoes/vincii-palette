# Palette

App **desktop multiplataforma** (Electron 41, JavaScript puro, sem framework) que reúne **várias contas do WhatsApp** num só lugar, com chamadas de voz e vídeo — o "WhatsApp Desktop" da Vincii para macOS, Windows e Linux. Cada conta é o **WhatsApp Web oficial** (`web.whatsapp.com`) carregado num `WebContentsView` com `partition` própria (`persist:wa-<id>`): sessões isoladas, como se cada número estivesse em outro computador. Não há protocolo não oficial nem automação — o app só organiza janelas, notificações e permissões. UI em pt-BR, identidade Vincii (dark, teal `#00C9B1`, Inter). Projeto irmão do Brush (`~/Desktop/Brush`), de onde vieram os padrões de empacotamento. Repositório **público** em `github.com/Vincii-Solucoes/vincii-palette` (estilo do Vincii Canvas: instaladores em Releases e auto-update por eles).

## Comandos

- `npm start` — abre o app em dev (`electron .`). Perfil em `~/Library/Application Support/Palette` (ou `PALETTE_USER_DATA=<pasta>`).
- `npm run smoke` — verificação sem interação (perfil temporário em `smoke.nosync/`): fotografa boas-vindas, diálogo de nova conta e configurações (`welcome|new-account|settings.png`), cria a conta "Conta teste", espera o WhatsApp Web (`account.png`, `shell.png`) e exercita o gerenciador (silenciar → flag na página, renomear, 2ª conta, alternar, reordenar, remover). `smoke.json` traz UA, título, permissões de mídia, patch de notificações, `steps` (modal/contentKey da barra em cada passo) e `modalLog` (quem abriu/fechou diálogos). Use depois de mexer no main/preload/renderer.
- `npm run assets` — regenera `build/icon.png` (1024px; electron-builder deriva .icns/.ico) e `assets/tray/*.png` com o monograma V da Vincii + selo de balão (`scripts/make-assets.js`, usa `sharp`).
- `npm run mac:install` — `scripts/package-mac.sh --install`: monta `Palette.app` só com ferramentas nativas (ditto/iconutil/plutil/codesign ad-hoc/hdiutil), gera o `.dmg` em `release.nosync/` e instala em `/Applications`. `mac:pack` não instala.
- `npm run dist` (`dist:mac|win|linux`, `pack` = só a pasta) — electron-builder; saída em `release.nosync/`. Nesta máquina a assinatura ad-hoc do `afterPack` falha com "detritus not allowed" (o iCloud re-marca os diretórios mesmo em `.nosync`), por isso o build local do macOS é o `mac:pack`/`mac:install` (monta em /tmp); no CI funciona. Instaladores oficiais saem do workflow `.github/workflows/release.yml` ao enviar tag `v*` (macOS dmg/zip arm64+x64, Windows nsis/zip, Linux AppImage/deb). Ao lançar versão, mude `version` no `package.json`. `build.publish` aponta para o repositório público: o electron-builder gera os `latest*.yml` do Release e o `electron-updater` (única dependência de runtime) os consulta — Windows/Linux baixam e aplicam, macOS avisa e abre a página (`setupAutoUpdate` em `main.js`; dormente em dev e nos builds do `package-mac.sh`, que não têm `app-update.yml`).
- Única dependência de runtime: `electron-updater`. `devDependencies`: electron, electron-builder, sharp.

## Arquitetura

- `src/main/main.js` — ciclo de vida: janela única (`BrowserWindow` com a barra lateral; no macOS `titleBarStyle: hiddenInset`), instância única, `app.setAppUserModelId` (Windows), menu, bandeja (só Windows/Linux — no macOS o app vive no Dock), badge de não lidas (`app.setBadgeCount` no mac/Linux; overlay desenhado pelo renderer no Windows), `flashFrame`, fechar = esconder (mac) ou bandeja (opção `closeToTray`), início com o sistema (`setLoginItemSettings`; no Linux `~/.config/autostart/palette.desktop`), links `whatsapp://send?phone=…` (handler de protocolo → `web.whatsapp.com/send/` na conta ativa; virar padrão é opção em Configurações, só no app empacotado), tema (`nativeTheme.themeSource`, padrão **escuro** — o WhatsApp Web segue o `prefers-color-scheme`; opção Escuro/Claro/Sistema em Configurações › Aparência), IPC da barra lateral e o modo smoke.
- `src/main/accounts.js` — `AccountManager`: uma `WebContentsView` por conta, todas montadas (mensagens, toques e chamadas seguem em segundo plano; `backgroundThrottling: false`), só a ativa visível (`setVisible`) à direita da barra (`RAIL_WIDTH` = 72), dentro de uma **moldura**: margem `FRAME_MARGIN` (12) e cantos `FRAME_RADIUS` (14, `view.setBorderRadius`); o renderer desenha borda, sombra e fundo escuro (`.frame`) 1px por fora da view. Não lidas vêm do título da página ("(3) WhatsApp" → `page-title-updated`). Links externos abrem no navegador; falha de rede mostra página offline que tenta de novo em 15 s; menu de contexto com correções ortográficas/links/imagens/edição. Remover conta apaga a partition (`clearStorageData`). Estado persistido: `accounts[]` (id, name, color, muted), `activeId`.
- `src/main/wa-session.js` — configura a partition: **user agent de Chrome** (sem "Electron/…" nem o nome do app — o WhatsApp Web recusa navegadores desconhecidos), permissões (`media`, `notifications`, clipboard, fullscreen, `display-capture`, `speaker-selection`; só para a origem do WhatsApp; no macOS pede ao TCC via `askForMediaAccess` antes de liberar), compartilhamento de tela (`setDisplayMediaRequestHandler` com `useSystemPicker` no macOS 15+; tela principal nos demais), corretor (`setSpellCheckerLanguages`, no macOS é o do sistema) e downloads direto na pasta Downloads.
- `src/preload/whatsapp.js` — único código que encosta na página: via `webFrame.executeJavaScript` envolve `window.Notification` no mundo da página para (a) avisar o clique (evento DOM `palette:notification-click` → IPC → janela na frente, na conta certa) e (b) silenciar a conta (`window.__paletteMuted` → notificações inertes). Sandbox + contextIsolation; nada exposto no `window`.
- `src/preload/shell.js` + `src/renderer/` (`index.html`, `styles.css`, `app.js`) — barra lateral em JS puro: avatares com iniciais e cor, badge, arrastar para reordenar, menu de contexto (renomear/cor, recarregar, silenciar, remover), boas-vindas sem conta, diálogos de conta e de configurações desenhados na área de conteúdo (enquanto abertos, `shell:modal` esconde as views). Estado vem inteiro do main (`shell:state`); comandos do menu chegam por `shell:command`.
- Auto-update: `setupAutoUpdate()` em `main.js` (acima). Página de releases: `RELEASES_URL`.
- `src/main/store.js` — JSON em `userData/palette.json` (contas, limites da janela, configurações), gravação atômica com debounce.
- Atalhos: ⌘/Ctrl+1…9 conta N, Ctrl+Tab/Ctrl+Shift+Tab alternar, ⌘/Ctrl+Shift+N nova conta, ⌘/Ctrl+R recarregar conta, ⌘/Ctrl+, configurações, ⌘/Ctrl+=/−/0 zoom da conta ativa.

## Convenções e armadilhas

- Cores só da paleta em `src/main/constants.js` (`ACCOUNT_COLORS`, tokens Vincii) e `:root` do `styles.css`; não hardcode fora daí.
- A pasta `~/Desktop` é iCloud com "Otimizar armazenamento": `node_modules` é symlink para `node_modules.nosync/`, `.git` é um arquivo `gitdir: .git.nosync`, builds vão para `release.nosync/` e o smoke para `smoke.nosync/`. `npm install` às vezes recria `node_modules` como pasta real — refaça `mv node_modules node_modules.nosync && ln -s node_modules.nosync node_modules`. Arquivos evictados travam Metro/electron-builder: `find . -path ./node_modules.nosync -prune -o -type f -flags +dataless -print` e `brctl download <arquivo>`.
- Chamadas dependem do WhatsApp Web oferecer chamadas no navegador (disponível para Chrome/Edge/Safari desde meados de 2026); o app só garante UA aceito, permissões de câmera/microfone e áudio em segundo plano. Sem Xcode/certificado Apple a assinatura é ad-hoc (ver `build/afterPack.js`); `build/entitlements.mac.plist` fica pronto para quando houver notarização.
- Limite do WhatsApp: até 4 aparelhos vinculados por número; cada conta aqui conta como um. Cada view é um processo de renderer (~150–300 MB por conta).
- `Alert`/`prompt` não existem no renderer: confirmações destrutivas usam `dialog.showMessageBox` no main (remover conta); diálogos de entrada são painéis do próprio renderer.
